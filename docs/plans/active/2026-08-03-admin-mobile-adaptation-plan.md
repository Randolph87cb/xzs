# 管理端手机适配方案

状态：active
创建日期：2026-08-03
完成日期：
验证摘要：

## 背景与现状

- 管理端位于 `frontend/apps/admin`，使用 Vue 3、Vite 和 Element Plus。
- 已确认路由中有 29 个实际业务页面入口，映射到 25 个业务页面组件；学生、老师、管理员列表及编辑入口复用 `UserListView.vue` 和 `UserEditView.vue`。
- 当前已有少量响应式样式：900px 以下会收窄侧栏、隐藏顶部页签，题目编辑会改成单列；练习观察和改错审核分别有独立的小屏断点。
- 当前还不能视为手机可用：侧栏仍常驻，页头操作较拥挤，多数列表仍是宽表格，分页器、固定宽度弹窗和复杂编辑台没有形成统一的手机交互。
- 老师角色当前开放练习观察、班级、学生、任务、答卷、改错审核和个人资料，适合优先作为第一批手机使用场景。

## 结论

先完成登录、导航和通用页面框架，再让老师与管理员的高频查询、发布和审核功能可在手机上独立完成；复杂组卷、题目生产和系统级配置暂不追求手机操作，只保证不会破坏页面和桌面端功能。

## 优先级定义

- **P0 基础前置**：不完成就无法稳定使用其他手机页面。
- **P1 第一批上线**：手机高频、老师或管理员在外出和课堂场景中确实会操作。
- **P2 第二批补齐**：以查询和轻量维护为主，频率较低，但改造成本可控。
- **P3 暂缓**：复杂内容生产、批量处理或高风险配置，手机收益低且误操作风险高。

## P0/P1 详细修改方案

### 1. P0：管理端整体布局

- 当前现状：`AdminLayout.vue` 始终渲染桌面侧栏；折叠后仍占 64px，顶部同时显示搜索、通知、帮助、头像、用户名和退出按钮。现有搜索、通知和帮助按钮没有业务处理函数。
- 判断：移动端只保留菜单入口、当前页面标题和账号菜单；不在本次适配中补做尚未实现的搜索、通知和帮助功能。
- 修改方案：
  1. 在布局内增加 `mobileMenuOpen`，菜单按钮在 767px 以下控制侧栏滑入/滑出，在桌面继续控制折叠状态。
  2. 保留同一份侧栏菜单 DOM，移动端通过固定定位、遮罩和 `transform` 实现抽屉，避免复制菜单和权限逻辑。
  3. 监听路由变化后关闭移动菜单；遮罩点击和 `Escape` 均可关闭；菜单按钮提供 `aria-expanded` 和明确标签。
  4. 手机顶部标题显示 `route.meta.title`；隐藏无行为的搜索、通知和帮助按钮。
  5. 手机账号区改为头像下拉菜单，只保留“个人资料”和“退出”；桌面现有用户区保持不变。
  6. 主内容区使用 `min-width: 0`，手机内边距调整为 12px，并加入顶部和底部安全区处理。
- 影响文件：`frontend/apps/admin/src/layouts/AdminLayout.vue`、`frontend/apps/admin/src/styles/index.scss`。
- 风险或边界：不改变 `adminMenus`、老师菜单过滤、路由权限和登录态；桌面侧栏折叠偏好继续沿用现有 localStorage。
- 验证方案：360px、390px、430px 下完成打开菜单、二级菜单跳转、遮罩关闭、路由后自动关闭、个人资料跳转和退出；1440px 下验证折叠偏好不退化。

### 2. P0：通用页面与响应式规则

- 当前现状：`.admin-page__header`、`.admin-page__filters`、`.admin-page__pagination` 只有桌面规则，表单常用固定 `label-width`，多数 Element Plus 控件不会自动占满窄屏。
- 判断：先建立统一的 767px 手机断点，页面只补业务特有样式；900px 继续作为平板/窄桌面断点。
- 修改方案：
  1. 在全局样式增加 `.desktop-only` 和 `.mobile-only`，供高频列表在桌面表格与手机卡片之间切换。
  2. 手机页头改为纵向布局，标题、说明和操作区各占一行；筛选区控件默认满宽，按钮区允许两列或整行。
  3. 表单在手机上覆盖为标签上置、内容区零左边距，输入框、选择器、日期选择器和数字输入占满可用宽度。
  4. 新增通用手机卡片、字段行、状态行、操作区样式，但各页面保留自己的字段顺序，不引入通用数据组件。
  5. 分页在手机上隐藏总数和每页数量选择，仅保留上一页、有限页码和下一页；桌面布局不变。
  6. 对话框统一限制为 `calc(100vw - 24px)`；任务选卷对话框另外使用近全屏高度和内部滚动。
  7. 主按钮、菜单项和卡片操作保持至少 44px 的可触控高度；粘性操作栏使用 `position: sticky`，不使用可能遮挡软键盘的全局 fixed。
- 影响文件：`frontend/apps/admin/src/styles/index.scss`，以及 P1 页面中的展示类名和手机卡片模板。
- 风险或边界：不全局把所有 `el-table` 强制卡片化，P2/P3 页面仍保留表格，以免不可控地破坏复杂表格。
- 验证方案：检查 360px 下无整页横向滚动；长标题、空值、错误提示、下拉浮层、确认框和软键盘场景不越界。

### 3. P0：登录页

- 当前现状：登录卡片已有最大宽度，但 34px 内边距和横向品牌区在小屏较挤；登录按钮同时绑定原生提交和点击事件。
- 判断：保留现有登录流程，只调整呈现并消除重复触发入口。
- 修改方案：
  1. 使用 `100dvh` 处理手机浏览器动态地址栏，360px 以下将页面和卡片内边距分别缩至 16px 和 22px。
  2. 品牌标题和说明允许换行，图标保持固定尺寸；输入框和登录按钮高度提升到触控尺寸。
  3. 登录仅通过表单 `submit` 调用 `handleLogin`，移除按钮额外的点击绑定；继续使用现有 `loading` 防重复提交。
  4. 校验错误保持在对应输入框下方，软键盘弹出时卡片允许自然滚动。
- 影响文件：`frontend/apps/admin/src/views/login/LoginView.vue`、`frontend/apps/admin/src/styles/index.scss`。
- 风险或边界：不改变记住登录、角色跳转和错误消息逻辑。
- 验证方案：空表单、错误密码、正确管理员登录、正确老师登录、回车提交和连续点击各验证一次。

### 4. P1：练习观察

- 当前现状：760px 以下筛选和摘要已经纵向排列，1180px 以下详情会排到矩阵下方；矩阵天然需要横向空间，点击学生后不会自动定位到下方详情。
- 判断：保留矩阵局部横向滑动和现有详情 DOM，不做新的抽屉组件。
- 修改方案：
  1. 手机页头与筛选使用 P0 通用规则，“查看”按钮满宽；隐藏无实际内容切换能力的辅助页签或改为静态说明。
  2. 为矩阵滚动容器增加边缘提示和触摸惯性，学生姓名列保持粘性；缩小日期列但不压缩到不可读。
  3. 点击学生后，在手机断点下使用 `nextTick` 将详情区平滑滚动到视口；关闭详情后将焦点返回原学生按钮。
  4. 摘要改为两列指标卡，图例允许换行；最近练习条目改为两行布局。
- 影响文件：`frontend/apps/admin/src/views/practice/PracticeObservationView.vue`。
- 风险或边界：矩阵容器允许横向滚动，不计为整页溢出；不修改练习数据接口和统计口径。
- 验证方案：覆盖无学生、7/14/30 天、长学生姓名、头像失败、选择不同学生、关闭详情和进入学生资料。

### 5. P1：改错审核

- 当前现状：1180px 以下队列、题目和审核面板顺序堆叠，手机需要在超长页面中来回滚动；页面加载后会自动选中第一条记录。
- 判断：手机使用“队列”和“审核详情”两步视图，桌面仍同时显示三列工作台。
- 修改方案：
  1. 增加仅用于视图控制的 `mobilePanel: 'queue' | 'detail'`；选择队列项后切到详情，详情顶部提供返回队列按钮。
  2. 桌面忽略该状态并继续显示全部区域；手机 CSS 每次只显示队列或详情，避免复制审核状态和请求逻辑。
  3. 查询和换页后回到队列；“保存并下一题”继续停留详情并加载下一条；无下一条时回到空队列提示。
  4. 审核结果、意见和保存操作放入粘性操作区；驳回意见校验仍沿用现有业务逻辑。
  5. AI 概览默认展开，AI 详细原因和审核历史改为折叠区；历史表格在手机上改卡片列表。
  6. 离开详情或返回队列时，如 `reviewFormEdited` 为真，弹出未保存确认，不能静默丢弃草稿。
- 影响文件：`frontend/apps/admin/src/views/question/QuestionCorrectionReviewView.vue`。
- 风险或边界：不改变 AI 预审、审核保存、草稿恢复和下一题选择算法；需要特别防止手机视图切换绕过现有草稿保护。
- 验证方案：覆盖筛选、分页、空队列、选择记录、AI 建议应用、通过、驳回无意见、驳回有意见、仅保存、保存并下一题、未保存返回确认。

### 6. P1：任务列表

- 当前现状：任务列表使用固定列宽表格，手机必须横向滚动才能看到编辑和删除操作。
- 判断：桌面保留表格，手机增加卡片模板；复用现有 `tasks` 数据和 `remove`、路由跳转函数。
- 修改方案：卡片顶部展示标题和班级，中部展示发送人与创建时间，底部提供编辑和删除；班级筛选与添加按钮满宽/并排；分页使用手机精简布局。
- 影响文件：`frontend/apps/admin/src/views/task/TaskListView.vue`、`frontend/apps/admin/src/styles/index.scss`。
- 风险或边界：删除继续使用现有二次确认，不新增批量操作。
- 验证方案：覆盖空列表、长标题、多页数据、按班级查询、编辑跳转、取消删除和确认删除。

### 7. P1：任务创建/编辑

- 当前现状：已选试卷与选卷弹窗都使用宽表格，弹窗固定 820px；提交按钮位于表单底部。

## 执行顺序

1. 完成 P0：登录、移动导航、通用卡片/表单/分页规则，并完成三种手机宽度的布局烟测。
2. 完成 P1 的只读高频页：练习观察、答卷列表、数据看板；先验证信息展示策略是否适合真机。
3. 完成 P1 的管理闭环：任务列表/编辑、学生列表/编辑、班级列表/编辑，并覆盖新增、修改、删除和未保存确认。
4. 完成 P1 的高交互流程：改错审核与个人资料，重点验证草稿保护、敏感配置边界和老师权限。
5. 增加手机自动化脚本，执行手机与桌面回归、生产构建、静态资源一致性校验和真实手机抽查。
6. P0/P1 验收通过后更新本方案状态；P2/P3 不进入本轮实施。

## 统一验收标准

- 360px 视口下不得出现整页横向滚动；明确允许横滑的矩阵和局部内容除外。
- 页面主操作无需缩放即可点击，按钮、输入框和选择项满足触控操作。
- 软键盘弹出时，当前输入框和提交按钮仍能被看到或滚动到。
- 抽屉、弹窗、下拉框和日期/选择组件不会超出视口。
- 危险操作继续有二次确认，高权限操作不得因手机适配降低权限校验。
- 老师角色无法进入未授权路由；管理员角色功能保持完整。
- 桌面 1440px 布局和现有操作不退化。
- 执行 `pnpm --dir frontend --filter @xzs/admin typecheck` 和 `pnpm --dir frontend --filter @xzs/admin build`。
- 执行现有 `pnpm --dir frontend verify:admin-ui` 与新增的 `pnpm --dir frontend verify:admin-mobile-ui`。
- 同步构建产物后通过 `scripts/verify-web-static-consistency.ps1`，不得使用 `-SkipHttpCheck` 代替运行服务验收。
- 使用真实手机浏览器完成老师与管理员两种角色的核心流程抽查。

## 风险与待确认

- 卡片列表可能需要在页面中维护桌面表格与手机卡片两种模板，应优先共享数据和操作函数，避免业务逻辑重复。
- “手机端只读/提示电脑操作”的 P3 页面需要产品层明确入口表现，避免用户误以为功能丢失。
- 练习矩阵本质上需要横向空间，首期保留局部横向滑动比强行压缩信息更可靠。
- 当前计划不包含管理员微信小程序、PWA 离线能力、后端接口变更或权限模型调整。
