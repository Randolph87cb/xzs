## 背景与现状

- 管理端位于 `frontend/apps/admin`，使用 Vue 3、Vite 和 Element Plus。
- 已确认路由中有 29 个实际业务页面入口，映射到 25 个业务页面组件；学生、老师、管理员列表及编辑入口复用 `UserListView.vue` 和 `UserEditView.vue`。
- 当前已有少量响应式样式：900px 以下会收窄侧栏、隐藏顶部页签，题目编辑会改成单列；练习观察和改错审核分别有独立的小屏断点。
- 当前还不能视为手机可用：侧栏仍常驻，页头操作较拥挤，多数列表仍是宽表格，分页器、固定宽度弹窗和复杂编辑台没有形成统一的手机交互。
- 老师角色当前开放练习观察、班级、学生、任务、答卷、改错审核和个人资料，适合优先作为第一批手机使用场景。

## 结论

先完成登录、导航和通用页面框架，再让老师与管理员的高频查询、发布和审核功能可在手机上独立完成；复杂组卷、题目生产和系统级配置暂不追求手机操作，只保证不会破坏页面和桌面端功能。

## 优先级定义

- **P0 基础前置**：不完成就无法稳定使用其他手机页面。
- **P1 第一批上线**：手机高频、老师或管理员在外出和课堂场景中确实会操作。
- **P2 第二批补齐**：以查询和轻量维护为主，频率较低，但改造成本可控。
- **P3 暂缓**：复杂内容生产、批量处理或高风险配置，手机收益低且误操作风险高。

## 需求拆解

### 1. 公共手机导航与页面骨架

- 当前现状：已有桌面侧栏折叠和少量 900px 断点，没有真正的移动导航状态。
- 判断：必须先做，否则逐页适配仍会被整体布局限制。
- 修改方案：在布局层识别窄屏并使用抽屉菜单；通用样式覆盖页头、筛选区、分页和触控尺寸。
- 影响范围：全部管理端页面，但不改变路由、权限和接口。
- 验证方案：在 360×800、390×844、430×932 和桌面 1440×900 四类视口完成登录、菜单跳转和退出烟测。

### 2. 列表页手机呈现

- 当前现状：多数列表直接使用固定列宽的 `el-table`，手机只能横向滚动。
- 判断：高频页面需要卡片模式，不能仅依赖横向滚动。
- 修改方案：在窄屏切换为语义化卡片列表，桌面继续保留现有表格；筛选与分页统一响应式。
- 影响范围：任务、答卷、用户、班级及后续 P2 列表页面。
- 验证方案：使用真实接口数据覆盖长标题、空值、禁用状态、空列表、多页数据和危险操作确认。

### 3. 表单与审核流程

- 当前现状：表单标签宽度固定，部分弹窗宽度固定为 820px，复杂工作台并排展示。
- 判断：手机上应改为单列、全屏选择器和分步流程。
- 修改方案：标签上置、控件满宽、关键提交固定在底部；审核队列和详情采用两步导航。
- 影响范围：任务编辑、用户编辑、班级编辑、改错审核。
- 验证方案：覆盖新增、编辑、校验失败、网络失败、重复提交防护、返回未保存确认和保存成功跳转。

### 4. 复杂页面边界

- 当前现状：组卷、题目/题组编辑和质量审核依赖宽表格、多列工作台、富文本或公式编辑。
- 判断：完整手机适配投入高，且不符合主要使用场景。
- 修改方案：首期不重构，窄屏给出明确电脑端提示；保留查看能力时必须避免可误触的保存或批量操作。
- 影响范围：P3 页面。
- 验证方案：手机访问不会布局崩溃，不会误提交；桌面功能保持原样。

## 执行顺序

1. 完成 P0：登录、移动导航和通用样式。
2. 完成 P1 的只读高频页：练习观察、答卷列表、数据看板。
3. 完成 P1 的管理闭环：任务列表/编辑、学生列表/编辑、班级列表/编辑。
4. 完成 P1 的高交互流程：改错审核、个人资料。
5. 真机验收第一批并修复共性问题。
6. 按实际使用反馈选择性完成 P2。
7. P3 保持桌面优先，只有明确出现手机端使用需求时另立方案。

## 统一验收标准

- 360px 视口下不得出现整页横向滚动；明确允许横滑的矩阵和局部内容除外。
- 页面主操作无需缩放即可点击，按钮、输入框和选择项满足触控操作。
- 软键盘弹出时，当前输入框和提交按钮仍能被看到或滚动到。
- 抽屉、弹窗、下拉框和日期/选择组件不会超出视口。
- 危险操作继续有二次确认，高权限操作不得因手机适配降低权限校验。
- 老师角色无法进入未授权路由；管理员角色功能保持完整。
- 桌面 1440px 布局和现有操作不退化。
- 执行管理端构建与类型检查，并通过 `scripts/verify-web-static-consistency.ps1`。
- 使用真实浏览器分别完成手机视口和桌面视口的核心流程烟测。

## 风险与待确认

- 卡片列表可能需要在页面中维护桌面表格与手机卡片两种模板，应优先共享数据和操作函数，避免业务逻辑重复。
- “手机端只读/提示电脑操作”的 P3 页面需要产品层明确入口表现，避免用户误以为功能丢失。
- 练习矩阵本质上需要横向空间，首期保留局部横向滑动比强行压缩信息更可靠。
- 当前计划不包含管理员微信小程序、PWA 离线能力、后端接口变更或权限模型调整。
