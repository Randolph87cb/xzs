# CSP 程序阅读与程序填空题组化改造方案

状态：completed
创建日期：2026-08-01
完成日期：2026-08-02
验证摘要：题组模型、旧新试卷框架兼容、单元级智能训练、管理端/学生端/微信小程序展示及 CSP 幂等同步均已实现；后端 102 项测试、前端类型检查与构建、静态资源一致性、Fly V9 迁移、Neon test 600 题/70 题组/14 套试卷核对和真实浏览器验收均通过。

## 背景与现状

- 当前 `t_question.question_type` 表示作答与判分方式：单选、多选、判断、填空、简答。它不是试题的内容结构类型，直接参与答案保存、判分和前端答题控件选择。
- CSP 程序阅读和程序填空目前被拆成多条普通 `t_question`。每个子题的 `titleContent` 都带有同一段程序、材料和同组其它小题，因此题库、试卷答题页和错题详情会反复显示大段相同题面。
- 当前试卷框架保存在 `t_exam_paper.frame_text_content_id` 指向的 JSON 中，每个标题下只有扁平的 `questionItems`，条目只记录 `id` 和 `itemOrder`。
- 当前答卷与答题明细都按普通问题 ID 保存，`t_exam_paper_question_customer_answer.question_id` 可以继续绑定子题；题组本身不需要生成答题记录。
- 当前智能训练通过 `QuestionMapper.selectRandomBySubjectId*` 对 `t_question` 逐题 `ORDER BY random()`，因此同一程序的子题会被拆散抽取。
- 当前学生 Web 答题页按扁平 `questionItems` 渲染，首屏分批渲染也按子题数量截断；若引入题组，必须避免同一题组被拆成两个渲染批次。
- CSP 原始题库 `docs/question-bank/CSP/raw/all.json` 已包含 `parentProblemNo`、`subQuestionNo`、`stemMarkdown`、`import_source` 和稳定 `question_code`。静态统计结果为：
  - CSP 客观题总数 600；
  - 14 套真题，每套有 5 道复合题；
  - 复合题共 70 道、子题共 390 道；其中程序阅读 42 道/250 个子题，程序填空 28 道/140 个子题；
  - 独立题 210 道；
  - 复合题包含 4 至 7 个子题，绝大多数为 5 或 6 个。
- 原始数据已经提供稳定父子关系，不应使用题面哈希或文本相似度推测分组。

## 结论

新增独立的“复合题/题组”模型，并以 `group_type` 区分“程序阅读”和“程序填空”；现有 `question_type` 继续只表示子题的作答方式。题组只保存一次共享题面，子题保留现有题目 ID、答案、分值、解析和答题记录。固定组卷与智能训练都把题组视为不可拆分的抽题单元，落到试卷和答卷时再展开为连续的子题答题项。

不推荐直接给 `QuestionTypeEnum` 增加“程序阅读题”或“程序填空题”：这会迫使题组本身进入现有判分分支，同时无法表达题组下混合存在判断题、单选题和多选题的真实情况。

## 推荐数据模型

### 1. 新增题组主表

新增 Flyway 迁移 `V9__add_composite_question_groups.sql`，创建 `t_question_group`，建议字段如下：

- `id`：题组主键；
- `group_type`：结构类型，`1=程序阅读`、`2=程序填空`，后续可扩展材料题但本次不预留未使用的 UI；
- `subject_id`、`grade_level`：所属科目与级别；
- `difficult`、`knowledge_point`：用于列表过滤和随机规则，属于整道大题；
- `info_text_content_id`：共享题面，只保存程序、材料、输入输出说明和公共提示；
- `group_code`：稳定题组编号，例如 `CSP-2021-S1-G016`；
- `import_batch`、`import_source`、`import_parent_order`：稳定导入定位字段；
- `create_user`、`status`、`create_time`、`deleted`：沿用现有软删除和状态习惯。

唯一约束建议为 `(import_batch, import_source, import_parent_order)` 的条件唯一索引；同时为 `subject_id + group_type + status + deleted`、`knowledge_point + status + deleted` 建查询索引。

### 2. 子题继续使用现有题目表

在 `t_question` 增加：

- `question_group_id`：可空，指向所属题组；
- `group_item_order`：可空，表示组内顺序。

约束：

- 两个字段必须同时为空或同时非空；
- `(question_group_id, group_item_order)` 在有效子题中唯一；
- 一个子题最多属于一个题组；
- 激活题组时至少有一个有效子题，CSP 回填校验要求每组实际为 4 至 7 个；
- 题组与子题的 `subject_id` 必须一致，由服务层在保存、换组和组卷时校验。

不新增题组答题表。学生答案、得分、错题、订正和历史记录仍然指向原来的子题 ID，以避免迁移历史答卷。

### 3. 初始化脚本与迁移边界

- 已运行环境只通过新的 V9 迁移升级，不修改既有 V1，避免 Flyway checksum 漂移。
- 同步更新 `sql/xzs-postgresql.sql`，保证新建数据库直接具备相同结构。
- 生产数据回填使用可重复执行、带前置检查和结果核对的 CSP 导入/迁移脚本，不把 70 道题组的数据硬编码进 Flyway DDL。

## 需求拆解

### 1. CSP 数据回填与题面去重

- 当前现状：每个程序类子题都保存整段公共程序和同组小题，题目 ID 与历史答题已经稳定使用。
- 判断：可以无损保留子题 ID，只新增题组并改写子题的题干 JSON；历史答题外键和得分无需变化。
- 修改方案：
  1. 修改 `scripts/prepare-csp-objective-questions.ps1` 和 `scripts/import-csp-objective-questions.ps1`，先按 `(import_source, parentProblemNo)` 聚合；只有组内数量大于 1 的记录生成题组，数量为 1 的仍为独立题。
  2. 同一试卷内按复合题出现顺序识别前三组为程序阅读、后两组为程序填空；同时把识别结果写入生成清单，并以 14 套试卷均为 `3+2` 结构作为强校验，不能仅靠题面是否含“阅读程序/完善程序”判断，因为后续题组可能省略章节标题。
  3. 从原始 `stemMarkdown/rawText` 提取共享题面，从每条 `stemMarkdown` 末尾的“子题 N：”提取单个子题题干；子题选项继续使用结构化 `options`。程序阅读题共享题面要剥离后面的整组判断题/选择题列表，程序填空题共享题面要保留说明和带空位程序、剥离末尾“①处应填”等问题清单。
  4. 对不能可靠拆分的题组写入质量报告并终止导入，不允许把空题面、整组重复题面或仅图片占位静默写入数据库；70 道题组应生成可人工抽检的父题/子题对照清单。
  5. 先 upsert 题组，再按现有稳定键 upsert 子题并写入 `question_group_id/group_item_order`。独立题必须清空这两个字段。
  6. 保留所有现有子题的 `id`、`question_code`、答案、分值、解析、难度、知识点和导入顺序；只把公共内容上移到题组，并把子题标题收窄为自身问题。
- 影响范围：CSP 准备、导入、解析生成和远端同步脚本，`t_question`/`t_text_content` 数据，题库导入说明。
- 验证方案：导入前后均为 600 个有效子题；70 个题组、390 个题组子题、210 个独立题；每组子题顺序连续且无重复；每个子题答案/分值/解析/稳定编号前后一致；抽检 14 套试卷共 70 组的共享题面不包含重复的小题选项列表。

### 2. 后端题组管理与查询

- 当前现状：后端只有普通题目的 domain、mapper、service、controller 和编辑 DTO。
- 判断：题组应拥有独立 CRUD，子题保存仍复用现有 Question 判分模型；普通题接口需要暴露可选的题组归属信息。
- 修改方案：
  1. 新增 `QuestionGroup`、`QuestionGroupTypeEnum`、mapper/service/controller 以及管理端列表、详情、编辑 DTO。
  2. 题组详情返回共享题面和有序子题；保存题组时在一个事务内保存父题、子题及顺序，拒绝跨科目子题、重复子题和空的有效题组。
  3. 普通题列表增加“独立题/题组子题”筛选和 `questionGroupId` 展示字段；默认选题接口只返回独立题，避免老师误把某个子题单独加入新试卷。
  4. 单题详情、错题详情、订正详情和 AI 预审上下文在子题属于题组时附带共享题面；AI 分析不能只看到被缩短后的子题标题。
  5. 软删除题组时不物理删除历史子题或答案；已被试卷引用的题组不能直接改变该试卷快照中的子题集合。
- 影响范围：`domain`、`repository`、`service`、管理端 controller/viewmodel、学生端单题/错题 DTO、AI 预审上下文。
- 验证方案：CRUD 事务、顺序唯一、跨科目拒绝、软删除、历史题可读、普通题查询不泄漏组内子题，以及带父题上下文的错题/订正接口集成测试。

### 3. 试卷框架支持独立题与题组

- 当前现状：试卷框架 JSON 只保存扁平 `questionItems`，无法表达“这一组子题必须整体出现”。
- 判断：试卷需要保存抽题单元，同时继续保存子题 ID 与全卷 `itemOrder` 快照，保证题组后续编辑不会改变已生成试卷的题数和答案顺序。
- 修改方案：
  1. 将标题下的持久化条目升级为统一 `paperItems`：`QUESTION` 保存单题 ID；`QUESTION_GROUP` 保存题组 ID，并快照保存本次入卷的全部子题 ID、组内顺序和全卷答题顺序。
  2. 后端读取时兼容旧 `questionItems` JSON，把旧条目映射为 `QUESTION`；新建和重新保存的试卷写新结构。无需一次性重写所有非 CSP 旧试卷。
  3. CSP 真题同步脚本重建 14 套试卷框架：210 个独立题按普通单元保存，70 个复合题按题组单元保存；子题全卷编号、总分和可作答题数保持原值。
  4. `t_exam_paper.question_count` 继续表示可作答子题数，不改成大题数；总分继续累加子题分值。可在 DTO 中额外返回 `paperItemCount` 供界面展示“大题数”，但本次不新增数据库冗余列。
  5. 提交答案仍只提交扁平子题 `questionId + itemOrder`，现有判分服务和答题明细表不新增题组分支。
- 影响范围：试卷 frame 对象、试卷编辑 DTO、`ExamPaperServiceImpl`、CSP 试卷同步脚本和前端 API 类型。
- 验证方案：旧试卷可原样读取；新题组试卷序列化/反序列化一致；同一题组的子题连续且完整；保存前后 `question_count`、总分、子题 ID 和 `itemOrder` 不变；历史答卷仍能读取和判分。

### 4. 随机抽题改为按抽题单元执行

- 当前现状：智能训练直接随机普通题，同一程序的多个子题可能只出现一部分，或在一次训练中出现多个带重复题面的子题。
- 判断：随机候选必须先分为“独立题单元”和“题组单元”，选中题组后一次展开全部子题。
- 修改方案：
  1. 普通随机 SQL 排除 `question_group_id IS NOT NULL` 的子题；新增题组候选查询，一次取回有效题组及全部有效子题。
  2. 内部建立 `QuestionSelectionUnit`：独立题成本为 1，题组成本为子题数量。随机算法选择单元，绝不选择单个题组子题。
  3. 智能训练配置中的 `questionCount` 继续表示最终答题项数量；选中 6 子题题组就消耗 6 个名额。采用随机化的可达性/回溯选择保证尽量精确命中目标数量，剩余名额可由独立题填充；如果在当前过滤条件下不存在完整组合，明确返回“无法在不拆题组的前提下生成 N 题”，不静默少题或拆组。
  4. 知识点规则对独立题使用子题知识点，对题组使用题组知识点；`minCount/maxCount` 仍按最终答题项数量计算，题组的全部子题共同消耗该规则配额。现有 GESP 题目均为独立题，行为保持不变。
  5. 展开题组后按题组内顺序分配连续的全卷 `itemOrder`，再生成试卷框架。
- 影响范围：`QuestionMapper`、智能训练计数与随机服务、智能训练配置校验、生成试卷框架逻辑。
- 验证方案：多次随机均不出现半个题组、组内顺序错乱或同一子题重复；目标数量可达时精确命中；不可达时显式失败；GESP 旧规则的题数和知识点上下限仍通过；固定随机种子的服务测试覆盖题组与独立题混合场景。

### 5. 管理端题组编辑与组卷体验

- 当前现状：题目管理和试卷编辑都只认识普通题，试卷编辑器会逐题加入和删除。
- 判断：题组必须以一行/一卡片作为管理和组卷单元，不能在组卷页面单独删除其中一个子题。
- 修改方案：
  1. 新增“题组管理”入口，支持按科目、题组类型、知识点和来源筛选。
  2. 题组编辑页上方编辑共享题面、类型、难度和知识点；下方以有序子题列表编辑每个子题的作答题型、题干、选项、答案、分值和解析。
  3. 试卷编辑器把“添加题目”拆为“添加独立题”和“添加题组”；题组选择列表显示共享题面摘要、类型、子题数、总分和来源。
  4. 已加入试卷的题组显示为一个可排序、可删除的整体，展开后只读查看子题；不提供在试卷内删除单个子题的操作。
  5. 普通题编辑页若打开题组子题，提示其所属题组并引导回题组编辑，避免绕过题组事务修改结构。
- 影响范围：管理端路由、题目列表/编辑页、试卷编辑页、共享 API client 类型与接口。
- 验证方案：浏览器完成新建题组、调整子题顺序、加入固定试卷、整组排序/删除、重新打开试卷一致性验证；确认不能通过普通选题弹窗选中组内子题。

### 6. 学生 Web、阅卷/错题页与微信小程序展示

- 当前现状：学生 Web 和微信小程序按扁平子题渲染；错题详情只展示当前普通题内容。
- 判断：所有能单独展示 CSP 子题的入口都必须补父题上下文，否则去重后会丢失程序代码。
- 修改方案：
  1. 试卷详情按 `paperItems` 渲染：独立题沿用现有卡片；题组先显示一次共享题面，再在同一组内连续显示子题答题控件。
  2. 顶部答题导航和答案提交仍按子题 `itemOrder` 工作；点击子题编号滚动到组内对应子题。
  3. 分批渲染以大题单元为边界，不能显示题组前半部分后再异步补后半部分。
  4. 答题回看、答卷编辑、错题工作台、错题历史和订正页在展示某个组内子题时，先展示只读共享题面，再展示该子题、学生答案和解析。
  5. 微信小程序同步支持题组 DTO；后端保留旧试卷 frame 的读取兼容，但不依赖旧小程序继续正确展示已经去重的新 CSP 数据。Web 与小程序支持完成前，不执行生产题面去重。
- 影响范围：学生 Web `ExamDoView`、`ExamReadView`、`ExamEditView`、错题相关页面，微信小程序 exam/错题页面，API client 类型。
- 验证方案：真实浏览器检查程序代码只出现一次、所有子题均可作答、导航定位正确、提交得分正确、回看与错题页上下文完整；小程序至少完成开发者工具的题组真题答题和错题回看烟测。

### 7. 文档与维护脚本

- 当前现状：CSP 导入和真题试卷同步脚本都以 600 条独立题为唯一结构，验证也只核对扁平问题数量。
- 判断：新结构必须由同一原始清单可重复生成，避免数据库人工绑题。
- 修改方案：
  1. 更新 CSP 准备、导入、解析同步和试卷同步脚本，使题组清单成为统一中间数据。
  2. 更新 `docs/question-markdown-import.md` 和 CSP 题库 README，说明父题/子题字段、题面拆分规则和质量检查。
  3. 在同步脚本中增加题组统计、孤儿子题、跨科目、顺序断裂、重复公共题面、试卷半组引用和总分不一致检查。
  4. 本次不新增顶层目录，因此无需修改项目结构文档；若实施时新增专门的题组脚本目录，再同步 `docs/project-structure/`。
- 影响范围：`scripts`、题库文档和部署前验证入口。
- 验证方案：`-DryRun/-SqlOnly` 输出稳定；连续执行两次数据库结果一致；质量检查能主动拦截人为制造的漏子题、重复顺序和半组试卷。

## 推荐执行顺序

1. 先为 70 道题组生成只读迁移清单和题面拆分质量报告，人工抽检所有异常项，确定共享题面/子题题干边界。
2. 增加 V9 数据结构、题组后端 CRUD、旧/新试卷 frame 双读能力和自动化测试；此时不改生产题面。
3. 修改 CSP 导入与试卷同步脚本，在开发库/Neon test 回填 70 个题组并重建 14 套 CSP 试卷。
4. 完成管理端题组管理和组卷，再完成学生 Web、错题/订正、阅卷上下文与微信小程序展示。
5. 把智能训练随机逻辑切换为单元级选择，完成整组性、精确题数和 GESP 回归测试。
6. 在 Neon test 做完整导入、固定真题、智能训练、提交判分、答卷回看和错题回看验收，并运行 Web 静态资源一致性校验。

### 后端与 API

- 旧 frame 兼容、新 frame 往返、CSP 试卷展开顺序和题数/总分测试。
- 混合独立题与题组的提交判分、答题回看、错题/订正和 AI 上下文测试。

### 前端与真实行为

### 生产发布核对

- 发布前数据库备份可恢复；迁移日志无失败；应用启动健康检查通过。
- 生产只读统计符合 70 个题组、390 个组内子题、210 个独立 CSP 题和 14 套 CSP 真题。

## 风险与边界

- 最大风险不是父子关系，而是把 `rawText` 中“公共程序”和“整组问题列表”正确拆开。必须先产出质量报告并人工处理少量异常，不允许仅做正则批量覆盖后直接上生产。
- `questionCount` 推荐继续表示可作答子题数。若产品希望它改为“大题数”，会连带影响智能训练配置、试卷列表、答题历史和统计口径，属于另一项产品决策，不纳入本方案。
- 题组知识点按整组维护，子题原有知识点暂时保留给错题统计和历史兼容；智能训练选择题组时使用父题知识点，避免同组子题被多个规则重复候选。
- 固定试卷必须快照子题 ID 和顺序。后续编辑题组成员只影响新组卷，不自动改写已经生成的试卷和历史答卷。
- Web 与微信小程序必须都能显示父题上下文后，才能把生产子题题干去重；否则旧客户端会只看到孤立的小题。
- 当前工作树存在用户的未跟踪目录 `.playwright-cli/` 和 `output/`，本方案未修改或清理它们。
