# 改错审批题组上下文显示修改方案

状态：completed
创建日期：2026-08-04
完成日期：2026-08-04
验证摘要：后端相关测试 17/17 通过，管理端类型检查、生产构建和静态资源一致性通过；本地 Chromium 验证题组共享题面与当前子题各显示一次、兄弟子题为 0，独立题不显示题组区域；提交 `05cb1c48` 已部署 Fly 测试环境，健康、公开页面、机器状态和启动日志验收通过。Fly 默认管理员凭据不可用，真实业务数据页未直接覆盖，已作为明确残余风险记录。

## 背景与现状

- CSP 题组化后，题组共享题面存放在 `t_question_group.info_text_content_id` 对应的文本内容中，子题自身只保留“② 处应填”一类子题题干。
- 生产改错记录 65 对应题目 11276，属于题组 30 的第 2 子题；共享题面仍完整存在，说明不是导入或数据丢失问题。
- 管理端改错审批接口当前只返回子题内容，没有返回题组共享题面；审批页因此只能显示子题题干和选项。
- AI 预审服务已经单独读取共享题面，本次不修改 AI 预审链路。

## 结论

后端按当前改错记录的 `question_id` 单向关联其所属题组，只返回该题组共享题面及当前子题；前端在当前子题前显示共享题面，不查询、不返回、不渲染同组其他子题。

## 需求拆解

### 1. 后端审批接口补充当前题目的题组上下文

- 当前现状：`/api/admin/questionCorrection/page` 与 `/select/{id}` 共用的查询只关联 `t_question` 和子题文本。
- 判断：接口缺少 `question_group_id`、`group_item_order`、`question_group_title`，无法支持题组子题完整展示。
- 修改方案：
  - 由当前题目 `q.question_group_id` 左关联 `t_question_group` 与其文本内容；
  - 返回 `question_group_id`、`group_item_order`、`question_group_code`、`question_group_type`、`question_group_title`；
  - 不关联 `t_question_group` 下的其他 `t_question`，避免把其他子题带入响应；
  - 独立题上述字段保持为空。
- 影响范围：管理端改错队列与详情接口；不改数据库、不改学生答卷、不改 AI 预审接口。
- 验证方案：后端单元测试断言题组字段存在，并断言查询不存在按题组回查其他题目的 sibling join/聚合。

### 2. 管理端显示共享题面和当前子题

- 当前现状：审批页只把 `detail.title` 传给 `QuestionCorrectionContext`。
- 判断：题组子题缺失答题所需的程序、材料或说明。
- 修改方案：
  - API 类型补充题组上下文字段；
  - 题组子题在当前子题之前显示一个明确的“题组共享题面”区域，并标识题组类型/编号/当前为第几小题；
  - 原 `QuestionCorrectionContext` 继续只接收当前子题，保持选项、答案、解析逻辑不变；
  - 页面不接收、不循环、不渲染任何 `questionItems` 或兄弟子题集合；
  - 独立题不显示题组区域。
- 影响范围：Vue 3 管理端改错审批页及共享 API 类型；不修改学生端和已停用的小程序。
- 验证方案：类型检查、管理端构建、静态资源一致性校验，以及带题组数据与独立题数据的页面行为验证。

### 3. Fly 测试环境发布与验收

- 当前现状：Fly.io 为测试环境，连接 Neon `test` branch；项目规定必须通过 `scripts/deploy-fly-neon-test.ps1` 发布。
- 判断：本地行为验证通过后，需要在真实部署形态下确认健康、静态资源和审批接口契约。
- 修改方案：不新增部署机制，沿用现有 Fly 发布脚本导入测试环境 secret 并部署当前提交。
- 影响范围：仅 Fly 测试环境与 Neon `test`；不触碰树莓派生产和 Neon `production`。
- 验证方案：
  - 发布后运行 Fly HTTP 健康、学生页、管理页验收；
  - 运行真实浏览器登录页烟测；
  - 在具备测试账号/对应测试数据时验证改错审批题组页面；若 Fly 测试数据没有可用改错记录，则以本地全 mock 浏览器行为测试 + Fly 接口/构建一致性为验收边界并显式报告；
  - 检查 Fly 状态和近期启动日志，无启动或数据库错误。

## 风险与待确认

- 共享题面可能较长，审批面板继续使用现有内部滚动区域，避免挤压审核侧栏。
- 历史改错记录无需迁移，详情接口会实时按原 `question_id` 取得当前题组信息。
- 本方案明确不展示同组其他子题；若以后需要题组全貌，应另立需求，不在本次扩展。
- Fly 测试环境若缺少可登录账号或对应改错数据，不写入伪造生产数据；真实数据页面验收缺口必须显式报告。
